## 这是什么？

**DirectorPrompt** 是一款面向长篇故事创作与游玩的 AI 交互式叙事桌面软件。

在这里，你不需要扮演故事里的某个人物，也不会以角色身份出现在剧情中，而是坐在**导演席**上——以上帝视角下达剧情指令、设定叙事约束、调度时间与场景，由 AI 负责执笔演绎整个世界的运转。

市面上的角色扮演工具大多依赖“上下文硬塞 + 关键词触发世界书”，一旦故事变长，就会面临设定遗忘、逻辑崩坏和 Token 账单暴涨的问题。DirectorPrompt 从底层重新构建了一套专为长线叙事设计的支撑引擎：**向量语义检索、动态状态与阶段触发器、人物分类与单向关系网、一维时间线管理**，让单次对话能像真正的文字冒险游戏一样长期稳定地推进下去。

## 与传统角色扮演工具的区别

| 维度 | 常见角色扮演工具 | DirectorPrompt |
| :--- | :--- | :--- |
| **用户身份** | 扮演固定角色，以对话形式参与剧情 | 上帝视角导演，通过结构化指令调度全局 |
| **知识召回** | 依赖关键词或正则匹配，换个同义词就无法触发 | 向量语义检索，只要意思相近就能自动关联 |
| **记忆管理** | 靠加长上下文硬塞，越写越容易遗忘或失焦 | 语义相关度 + 时间衰减混合召回，原文永久保存，按需精准提取 |
| **状态系统** | 无，或仅靠提示词让 AI 自己记 | 原生支持数值、枚举、条件表达式，支持与知识库和指令联动的**阶段触发** |
| **时间线** | 只能单向往前聊，穿插回忆极易污染当前状态 | 内置一维时间轴，支持随时闪回、插叙，自动隔离不同时间点的记忆与状态 |
| **人物系统** | 单张角色卡独立定义，难以管理群像 | 支持人物分类与多重继承，自动维护登场建档、经历归档与单向关系网 |
| **游玩成本** | 对话越长，单次请求消耗越高 | 自动归档压缩上下文，严格保持消息前缀稳定，最大化命中 API 缓存 |

## 快速开始

### 环境要求

- Windows 11 或 Linux x64 桌面环境
- .NET 10 SDK
- （可选）Ollama，用于运行本地模型

### 下载与运行

前往 [Releases 页面](https://github.com/AtmoOmen/DirectorPrompt/releases) 下载对应平台的发布包：

- **Windows**：下载 `DirectorPrompt-win-Portable.zip`，解压后直接运行 `DirectorPrompt.exe`
- **Linux**：下载 `*.AppImage`，赋予可执行权限后直接运行

### 上手流程

1. 启动软件，打开**设置**界面，配置模型提供商与 API 密钥，并为叙事生成、后台代理任务及向量嵌入（Embedding）分别指定模型。
2. **创建新项目**，可以直接从零新建，也支持导入本软件的数据包或 SillyTavern 导出的角色卡。
3. 编写项目提示词，按需添加世界观知识条目、人物分类与状态变量，保存设置。
4. 在主界面底部输入区组合导演指令，点击发送，开始你的故事。

## 核心功能

### 1. 结构化导演指令

底部的输入区不是普通的聊天输入框，而是一个支持自由组合与排序的**导演指令台**：

- **剧情指令**：交代接下来要发生的事件或发展方向。
- **叙事约束**：规定文风或内容限制，支持设为永久生效、持续指定轮数后自动失效，或随时手动移除。
- **时间/场景变更**：切换故事当前所处的时间节点或场景地点。

**指令的排列顺序本身就代表叙事先后逻辑。** 例如先排“三天后”再排“主角发现密信”，和先“主角发现密信”再“三天后”，AI 会推演出截然不同的剧情走向。

### 2. 工具驱动的叙事创作

在 DirectorPrompt 中，叙事模型（需支持流式工具调用）不再是“一口气输出一段话就结束”，而是通过一套专用写作工具打磨每一轮草稿：

- **草稿打磨与定稿分离**：模型在创作时可以分段追加、局部精确替换、重写全文、检索草稿并统计字数。只有调用提交工具正式确认的草稿才会进入故事正文；中间的构思、普通回复与工具调用细节都收纳在可展开的“创作过程”面板中，保持正文干净纯粹。
- **分层上下文与历史翻阅**：项目设定、开场叙事、场景摘要及当轮状态、相关知识与记忆通过 `get_narrative_context` 分层提供，活跃历史轮次以 `read_story_round` 工具结果衔接并按水位线分批压缩归档，兼顾工具输出注意力与跨轮次前缀缓存命中。如果模型需要回顾已归档的早期剧情细节，可以调用 `list_story_scenes` 查找场景、`list_story_rounds` 分页浏览轮次，再用 `read_story_round` 按行读取历史原文。
- **叙事意图传递**：模型在创作时可以记录本轮的“叙事意图”（如埋下的伏笔、人物动机、状态变动原因），供后续处理代理参考；而实际的状态增减与记忆归档，则严格以正文中已经发生的事实为准。

### 3. 向量语义召回（知识与记忆）

传统工具靠关键词匹配触发设定，如果设定的触发词是“小巷”，当你输入“窄道”时就会匹配失败，逼着创作者没完没了地补充同义词。

DirectorPrompt 采用**向量语义检索**：系统会将文本交给 Embedding 模型转化为语义向量，直接按“意思有多相近”来检索知识与记忆。在 AI 看来，“巷子”“小巷”“窄巷”“窄道”语义高度相近，无论你怎么表述都能精准召回对应设定。

- **分组管理与剧透开关**：知识库支持分组与手动开关。你可以把后期才揭晓的核心反转或世界真相放进独立分组并暂时关闭，等剧情推进到关键时刻再手动开启，精准把控悬疑与叙事诡计的节奏。
- **拟真遗忘曲线**：历史记忆召回采用“语义相关度 + 时间线距离衰减”混合排序。久远事件的权重会像人类记忆一样自然降低，但原文永久保存在库中，一旦剧情需要随时能完整调出。
- **时间线自动过滤**：每条记忆都绑定其发生的时间线场景。当剧情切换到过去的时间点时，晚于该时间点的记忆会自动屏蔽，无需手动管理。

### 4. 动态状态栏与“阶段”触发器

侧边状态栏会随剧情发展实时更新，支持为整个项目或特定人物类别定义专属状态：

- **数值型状态**：如金钱、声望、理智值。你只需设置上下限、单位和增减规则，AI 会根据正文发展自动计算并更新数值。
- **枚举型状态**：如天气、季节、昼夜。系统会根据设定的触发时机自动切换状态，支持两种模式：
  - **随机模式**：为每个枚举项设置权重概率，到时机后按概率随机切换。
  - **表达式模式**：关联其他状态编写条件表达式，满足条件时自动流转到对应枚举项。

**“阶段”是状态系统的灵魂机制**：你可以编写条件表达式，当状态达到特定值、进入或离开某个区间时，**自动解锁隐藏知识条目**，或**自动下发一组预设指令**。

> **示例**：设定当 `理智值 ≤ 50` 时，自动注入隐藏知识《世界的隐秘真相之三》，并自动附加两条持续 3 轮的叙事约束：
> - `（叙事约束，持续 3 轮）` 环境氛围变得压抑
> - `（叙事约束，持续 3 轮）` 理智值无法恢复至大于 50 的值
>
> 借助阶段机制，你不必靠人脑记规则、手动发约束，就能做出真正具备游戏程序逻辑的交互体验。

### 5. 人物分类与单向关系网

为了贴合第三人称导演视角，软件采用**人物分类**而非传统的单一角色卡来组织人物体系：

- **多重继承与专属状态**：人物分类支持多重继承，并可挂载独立的状态栏（例如为“修仙者”分类挂载境界与灵力状态）。
- **有向关系网络**：人物之间的关系与记忆是单向独立的——A 对 B 的评价与印象，和 B 对 A 的评价与印象可以完全不同。
- **全自动建档维护**：新人物在正文中登场时自动建档，离场时自动更新状态；随着剧情推进和关系变化，AI 会在后台自动提取并更新每个人物的经历档案，全程无需手动维护。

### 6. 一维时间线与无缝闪回

软件内置一维时间坐标轴，平时顺叙推进自然流畅；当你想穿插回忆、倒叙或支线闪回时，只需在指令中加入一条**时间/场景变更**指令，系统就会自动将新场景插入正确的时间节点。

处于较早的时间节点时，系统会自动过滤掉未来才会发生的记忆、知识与状态，且在回忆场景中产生的状态与记忆变动不会污染最新时间线，切换体验完全无感。

### 7. 上下文压缩与缓存优化

长篇创作最怕历史记录撑爆上下文，不仅 API 费用高昂（尤其是两次游玩间隔超出缓存有效期时），还会导致模型注意力分散、文笔退化。

- **自动归档压缩**：当发生时间/场景切换，或上下文长度超出设定预算时，系统会自动将早期内容压缩提炼为记忆存入数据库，让活跃上下文始终保持精炼。
- **高缓存命中率**：已完成轮次的请求与工具调用记录在预算内按原顺序保留，所有模型与后台代理调用都会尽量维持消息前缀稳定，在单次游玩过程中最大化命中模型提供商的 Prompt 缓存，显著降低调用成本。

### 8. 全状态精准回滚

对话过程中的每一次文本生成、状态数值变更、人物建档与记忆写入，都会作为完整的事件序列记录下来。

当你对某一轮的发展不满意、点击回滚时，系统不仅会撤回生成的正文，还会将这一轮引起的状态、人物、记忆变更全部精准还原，并把当时的导演指令自动填回底部输入区，方便你修改后重新开拍。

### 9. 工具生态与 MCP 双向集成

软件内部将人物、状态、知识、记忆、场景等所有核心能力全部封装为标准工具，供 AI 代理按需调用。

同时支持 **MCP（Model Context Protocol）双向协议**：既可以接入外部 MCP 服务为 AI 扩展更多工具能力，也可以将 DirectorPrompt 自身的叙事控制工具作为 MCP 服务对外暴露，让外部工作流也能灵活操控故事发展。

## 模型思考（Reasoning）配置指南

展开每轮的“创作过程”，可以查看模型接口公开返回的推理思考文本或摘要（注：部分模型虽在内部执行推理，但接口仅返回加密签名供后续工具调用使用，此类加密数据不会显示为文本）。

不同模型提供商的配置方式如下：

| 接口与模型 | 提供商类型与端点 | 思考配置说明 |
| :--- | :--- | :--- |
| **Gemini**（OpenAI 兼容接口） | 类型：`openai`<br>端点：`https://generativelanguage.googleapis.com/v1beta/openai/` | 自动请求 `include_thoughts`；推理强度可留空以使用服务端默认值 |
| **OpenAI GPT / o 系列** | 类型：`openai-responses`<br>端点：`https://api.openai.com/v1` | 支持推理的模型会自动请求思考摘要；按模型支持范围填写推理强度 |
| **Claude**（Messages API） | 类型：`anthropic` | 推理强度支持填写 `low`、`medium`、`high`、`xhigh`；较早型号采用 Token 预算，Sonnet / Opus 4.6 及后续版本采用自适应思考 |
| **DeepSeek / Kimi / GLM** | 类型：`openai`<br>端点：对应服务的 OpenAI 兼容地址 | 已开启思考的模型会直接显示推理内容；配置推理强度时会发送对应的 `thinking` 开关（填 `none` 表示关闭） |
| **Qwen / QwQ** | 类型：`openai`<br>端点：对应服务的 OpenAI 兼容地址 | 配置推理强度时会发送 `enable_thinking` 参数；能否关闭思考以服务端实际支持范围为准 |
| **OpenRouter** | 类型：`openai`<br>端点：`https://openrouter.ai/api/v1` | 配置推理强度时使用其 `reasoning` 参数；接口公开返回的推理详情会显示在思考区域 |
| **Grok、其他兼容接口及本地模型** | 类型：`openai` 或 `ollama` | 自动解析响应中的 `reasoning_content`、`reasoning`、`thinking`、`reasoning_details` 字段，以及流式输出中的 `<think>`、`<thinking>`、`<analysis>` 标签 |

### 自定义请求参数

如需覆盖默认行为，可在模型的“自定义参数”中直接填写请求 JSON 字段（显式配置的字段优先级高于系统自动生成的同名字段）：

- **Gemini 示例**：`{"extra_body":{"google":{"thinking_config":{"include_thoughts":true,"thinking_budget":8192}}}}`（注：自定义 `thinking_budget` / `thinking_level` 时不会与推理强度同时发送）
- **Qwen 示例**：`{"enable_thinking":true}`

> 若使用第三方中转网关，是否返回思考内容以及支持哪些额外参数均取决于网关自身的实现。
>
> **官方接口文档参考**：[Gemini](https://ai.google.dev/gemini-api/docs/openai) · [OpenAI 推理](https://platform.openai.com/docs/guides/reasoning) · [Claude 思考](https://platform.claude.com/docs/en/build-with-claude/extended-thinking) · [DeepSeek](https://api-docs.deepseek.com/guides/thinking_mode) · [Kimi](https://platform.moonshot.ai/docs/guide/use-thinking-models) · [Qwen](https://www.alibabacloud.com/help/en/model-studio/deep-thinking) · [GLM](https://docs.bigmodel.cn/cn/guide/capabilities/thinking) · [OpenRouter](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)
